# Visible Acceptance Review - 2026-06-01

Status: Current review snapshot.

## Scope

This review checks the local visible acceptance demo generated by:

```bash
npm run visible:demo -- --out <workspace> --serve
```

Current inspected URL:

```text
http://127.0.0.1:54889/verify/index.html
```

The purpose is not to decide whether the example organization is trustworthy. The purpose is to check whether a human can see the same major state that an AI agent reads from the machine package.

## Result

Decision: PASS FOR FIRESEED VISIBLE ACCEPTANCE, WITH LANGUAGE GAP DISCLOSED.

The current page is good enough to show the first public Fireseed loop:

```text
signed identity -> generated verify page -> agent-readable JSON -> compact verification -> tamper failure
```

It is not yet a finished multilingual product surface.

## What Passed

- The page has a clear organization header.
- The page has a `How to Read This Page` section that gives a first-pass review order.
- It shows that the statement is signed.
- It shows root authority threshold information.
- It shows a visible proof trail.
- It includes `Agent Verification View`.
- It exposes `Overall status`, `Identity status`, `Value status`, `Conformance`, and `Trust decision`.
- It exposes S1-S5 evidence classes without pretending missing classes are present.
- It exposes `External Policy Route`.
- It exposes `Next Checks`.
- It links the human-readable page to the machine-readable package.
- The demo includes a tamper-failure path where changing the signed statement produces identity failure.

## What Needs Improvement

1. The page is English-only.

The current HTML declares `lang="en"` and has no localized page variants. This is acceptable for Fireseed Alpha, but not enough for broad global adoption.

2. Some terms are still too technical for non-developers.

Examples:

- `Root authority`
- `Conformance`
- `External Policy Route`
- `Trust decision`
- `S1 First-party`
- `S3 Sampling`

These terms are correct, but the page should eventually provide a short glossary or localized explanation layer.

3. `S4 Observation` and `S5 Challenge` may be misunderstood.

The page correctly marks them as design preview / not included, but users may still think they are complete product features. Fireseed communication must keep saying S4/S5 are not acceptance gates yet.

4. The page is useful, but still not a polished onboarding surface.

It is enough for verification and review. It is not yet a friendly product studio, wizard, or education-first landing page.

## Language Compatibility Decision

OrgAnchor should support global use through a two-layer language model:

```text
Stable English machine contract
+ localized human explanation
```

Machine-readable keys, status values, policy route codes, schema identifiers, command names, and artifact filenames should not be translated.

Human-facing explanations, onboarding guides, glossary text, and future `/verify` page variants can be translated.

Reason:

If machine keys are translated, every language becomes a semi-new protocol. That would increase AI-agent parsing cost, Directory integration cost, and independent verifier implementation cost.

Therefore:

- `PASS`, `WARN`, `FAIL`, `FULL_COMPATIBLE`, `STOP_IDENTITY_FAILURE`, etc. remain stable protocol values.
- Chinese, English, Japanese, German, Spanish, and other pages may explain those values in local language.
- `/.well-known/organchor.json` and `/verify/organchor.json` remain the canonical machine entry points.
- localized pages must not hide warnings, missing evidence, or OrgAnchor's non-endorsement boundary.

See `LANGUAGE_COMPATIBILITY.md` for the active policy.

## Fireseed Readiness Impact

This review does not block Fireseed.

It creates one explicit Fireseed caveat:

```text
Fireseed visible acceptance is English-first. Multilingual human explanation is documented as a policy direction, not a finished feature.
```

- Do not create different schemas per language.
- Do not let localized text make stronger claims than the signed source material.
- Do not imply OrgAnchor certifies organization quality in any language.
